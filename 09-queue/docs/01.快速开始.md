## 环境准备

### 1. 安装依赖

```bash
cd 09-queue
npm install
```

### 2. 初始化数据库

```bash
# 本地开发环境
npm run db:local

# 生产环境
npm run db:migrate
```

### 3. 配置队列

在 `wrangler.toml` 中已配置 4 个队列：

- `task-queue`: 通用任务队列
- `email-queue`: 邮件发送队列
- `webhook-queue`: Webhook 处理队列
- `image-queue`: 图片处理队列

## 本地开发

### 启动开发服务器

```bash
npm run dev
```

服务将在 `http://localhost:8787` 启动。

## 队列类型

### 1. Task Queue（任务队列）

用于处理通用后台任务：

- 数据处理
- 定时清理
- 通知发送
- 报告生成

### 2. Email Queue（邮件队列）

用于异步发送邮件：

- 欢迎邮件
- 通知邮件
- 营销邮件
- 报告邮件

### 3. Webhook Queue（Webhook 队列）

用于处理 Webhook 事件：

- GitHub 事件
- Stripe 事件
- 自定义事件

### 4. Image Queue（图片队列）

用于处理图片任务：

- 图片缩放
- 图片优化
- 缩略图生成
- 水印添加

## API 使用示例

### 1. 发送单个任务到队列

```bash
curl -X POST http://localhost:8787/api/queue/send \
  -H "Content-Type: application/json" \
  -d '{
    "queue": "task",
    "type": "data_processing",
    "data": {
      "userId": "12345",
      "action": "export_data"
    },
    "options": {
      "priority": 5,
      "maxRetries": 3
    }
  }'
```

响应：

```json
{
  "success": true,
  "taskId": "uuid-...",
  "queue": "task",
  "message": "Task queued successfully"
}
```

### 2. 批量发送任务

```bash
curl -X POST http://localhost:8787/api/queue/batch \
  -H "Content-Type: application/json" \
  -d '{
    "queue": "email",
    "tasks": [
      {
        "type": "welcome",
        "data": {
          "email": "user1@example.com",
          "name": "张三"
        }
      },
      {
        "type": "welcome",
        "data": {
          "email": "user2@example.com",
          "name": "李四"
        }
      }
    ]
  }'
```

响应：

```json
{
  "success": true,
  "results": [
    { "taskId": "uuid-1", "success": true },
    { "taskId": "uuid-2", "success": true }
  ],
  "total": 2,
  "succeeded": 2,
  "failed": 0
}
```

### 3. 发送邮件任务

```bash
curl -X POST http://localhost:8787/api/queue/send \
  -H "Content-Type: application/json" \
  -d '{
    "queue": "email",
    "type": "notification",
    "data": {
      "email": "user@example.com",
      "subject": "系统通知",
      "body": "您有一条新消息"
    }
  }'
```

### 4. 发送图片处理任务

```bash
curl -X POST http://localhost:8787/api/queue/send \
  -H "Content-Type: application/json" \
  -d '{
    "queue": "image",
    "type": "resize",
    "data": {
      "imageUrl": "https://example.com/image.jpg",
      "width": 800,
      "height": 600
    }

```

### 5. 延迟任务（定时执行）

```bash
curl -X POST http://localhost:8787/api/queue/send \
  -H "Content-Type: application/json" \
  -d '{
    "queue": "task",
    "type": "cleanup",
    "data": {
      "target": "temp_files"
    },
    "options": {
      "scheduledAt": 1705334400000
    }
  }'
```

### 6. 去重任务

```bash
curl -X POST http://localhost:8787/api/queue/send \
  -H "Content-Type: application/json" \
  -d '{
    "queue": "task",
    "type": "notification",
    "data": {
      "userId": "12345",
      "message": "重要通知"
    },
```

## 重试机制

### 自动重试配置

每个队列有不同的重试配置：

- **task-queue**: 最多重试 3 次
- **email-queue**: 最多重试 5 次
- **webhook-queue**: 最多重试 3 次
- **image-queue**: 最多重试 2 次

### 重试策略

- 使用指数退避算法
- 超过最大重试次数后移入死信队列
- 可以从死信队列中手动重新处理

## 消息去重

### 自动去重

系统会根据消息内容自动生成 `messageId` 进行去重：

```javascript
const messageId = await generateMessageId({ type, data });
```

### 手动指定去重 ID

```bash
curl -X POST http://localhost:8787/api/queue/send \
  -H "Content-Type: application/json" \
  -d '{
    "queue": "task",
    "type": "sync",
    "data": {...},
    "options": {
      "deduplicate": true,
      "messageId": "custom-id-12345"
    }
  }'
```

去重窗口默认为 300 秒（5 分钟），可在环境变量中配置：

```toml
[vars]
DEDUPLICATION_WINDOW = "600"
```

## 性能优化

### 1. 批量处理

使用批量 API 一次发送多个任务：

```bash
curl -X POST http://localhost:8787/api/queue/batch \
  -H "Content-Type: application/json" \
  -d '{
    "queue": "task",
    "tasks": [...]
  }'
```

### 2. 调整批次大小

在 `wrangler.toml` 中配置：

```toml
[[queues.consumers]]
queue = "task-queue"
max_batch_size = 10        # 每批最多处理 10 条消息
max_batch_timeout = 30     # 最多等待 30 秒
```

### 3. 使用 R2 存储大 Payload

对于超过 128KB 的大型 payload，建议先上传到 R2，然后在消息中只传递引用：

```json
{
  "queue": "task",
  "type": "large_data_processing",
  "data": {
    "payloadUrl": "r2://bucket/large-payload-123.json"
  }
}
```

## 常见问题

### 1. 任务处理失败怎么办？

- 系统会自动重试
- 超过重试次数后移入死信队列
- 可以从死信队列中查看失败原因并手动重试

### 2. 如何保证消息不丢失？

- Cloudflare Queues 提供至少一次交付保证
- 使用 `message.ack()` 确认消息已成功处理
- 失败的消息会自动重试或移入死信队列

### 3. 如何处理大量任务？

- 使用批量 API
- 调整 `max_batch_size` 增加并发处理
- 考虑使用多个 Worker 实例

### 4. 队列延迟有多大？

- 通常在几秒到几十秒之间
- 取决于队列负载和批次配置
- 不适合需要实时响应的场景
