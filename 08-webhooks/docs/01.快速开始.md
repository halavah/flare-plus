## 环境准备

### 1. 安装依赖

```bash
cd 08-webhooks
npm install
```

### 2. 初始化数据库

```bash
# 本地开发环境
npm run db:local

# 生产环境
npm run db:migrate
```

### 3. 配置环境变量

在 `wrangler.toml` 中配置 Webhook 密钥：

```toml
[vars]
GITHUB_WEBHOOK_SECRET = "your_github_secret"
STRIPE_WEBHOOK_SECRET = "your_stripe_secret"
SLACK_WEBHOOK_SECRET = "your_slack_secret"
```

## 本地开发

### 启动开发服务器

```bash
npm run dev
```

服务将在 `http://localhost:8787` 启动。

## 配置 Webhook

### 1. GitHub Webhook

在 GitHub 仓库设置中添加 Webhook：

- **Payload URL**: `https://your-worker.workers.dev/webhooks/github`
- **Content type**: `application/json`
- **Secret**: 与 `GITHUB_WEBHOOK_SECRET` 相同
- **Events**: 选择需要的事件（push, pull_request, issues 等）

### 2. Stripe Webhook

在 Stripe Dashboard 中添加 Webhook：

- **Endpoint URL**: `https://your-worker.workers.dev/webhooks/stripe`
- **Events**: 选择需要监听的事件
- **Signing secret**: 复制到 `STRIPE_WEBHOOK_SECRET`

### 3. Slack Webhook

在 Slack App 设置中配置 Event Subscriptions：

- **Request URL**: `https://your-worker.workers.dev/webhooks/slack`
- **Signing Secret**: 复制到 `SLACK_WEBHOOK_SECRET`

## API 使用示例

### 1. GitHub Webhook

#### 接收 Push 事件

```bash
curl -X POST http://localhost:8787/webhooks/github \
  -H "Content-Type: application/json" \
  -H "X-GitHub-Event: push" \
  -H "X-Hub-Signature-256: sha256=..." \
  -d '{
    "ref": "refs/heads/main",
    "repository": {
      "full_name": "user/repo"
    },
    "commits": [...]
  }'
```

#### 接收 Pull Request 事件

```bash
curl -X POST http://localhost:8787/webhooks/github \
  -H "Content-Type: application/json" \
  -H "X-GitHub-Event: pull_request" \
  -H "X-Hub-Signature-256: sha256=..." \
  -d '{
    "action": "opened",
    "pull_request": {...}
  }'
```

### 2. Stripe Webhook

#### 接收支付成功事件

```bash
curl -X POST http://localhost:8787/webhooks/stripe \
  -H "Content-Type: application/json" \
  -H "Stripe-Signature: t=...,v1=..." \
  -d '{
    "type": "payment_intent.succeeded",
    "data": {
      "object": {
        "id": "pi_...",
        "amount": 1000,
        "currency": "usd"
      }
    }
  }'
```

### 3. Slack Webhook

#### URL 验证挑战

```bash
curl -X POST http://localhost:8787/webhooks/slack \
  -H "Content-Type: application/json" \
  -H "X-Slack-Signature: v0=..." \
  -H "X-Slack-Request-Timestamp: 1234567890" \
  -d '{
    "type": "url_verification",
    "challenge": "3eZbrw1aBm2rZgRNFdxV2595E9CY3gmdALWMmHkvFXO7tYXAYM8P"
  }'
```

#### 接收消息事件

```bash
curl -X POST http://localhost:8787/webhooks/slack \
  -H "Content-Type: application/json" \
  -H "X-Slack-Signature: v0=..." \
  -H "X-Slack-Request-Timestamp: 1234567890" \
  -d '{
    "type": "event_callback",
    "event": {
      "type": "message",
      "channel": "C1234567890",
      "user": "U1234567890",
      "text": "Hello!"
    }
  }'
```

### 4. 自定义 Webhook

```bash
curl -X POST http://localhost:8787/webhooks/custom \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Signature: abc123..." \
  -H "X-Event-Type: order.created" \
  -d '{
    "orderId": "12345",
    "amount": 99.99,
    "customer": "customer@example.com"
  }'
```

## 查询和统计

### 获取 Webhook 统计

```bash
# 所有提供商的统计

# 特定提供商的统计
curl http://localhost:8787/api/stats?provider=github&days=30
```


```bash

curl http://localhost:8787/api/events?provider=stripe&limit=20

# 按状态过滤

```

## 签名验证

### GitHub 签名验证

GitHub 使用 HMAC SHA-256 签名：

```
X-Hub-Signature-256: sha256=<signature>
```

### Stripe 签名验证

Stripe 使用时间戳和签名：

```
Stripe-Signature: t=<timestamp>,v1=<signature>
```

### Slack 签名验证

Slack 使用版本化签名：

```
X-Slack-Signature: v0=<signature>
X-Slack-Request-Timestamp: <timestamp>
```

## 重试机制

### 自动重试

- 最大重试次数：3 次
- 重试间隔：指数退避
- 超过重试次数后移入死信队列

### 手动重试

从死信队列中重新处理失败的 Webhook：

```bash
# 查询死信队列
curl http://localhost:8787/api/dlq?queue=webhook-dlq

# 手动重新发送（需要实现管理 API）
```

## 安全最佳实践

1. **始终验证签名**：确保 Webhook 来自可信来源
2. **使用 HTTPS**：生产环境必须使用 HTTPS
3. **速率限制**：防止 DDoS 攻击
4. **IP 白名单**：可选，限制特定 IP 访问
5. **日志审计**：记录所有 Webhook 事件

## 性能优化

1. **异步处理**：使用 Queue 异步处理 Webhook
2. **批量处理**：合并多个事件一起处理
3. **缓存配置**：使用 KV 缓存 Webhook 配置
4. **去重处理**：防止重复处理相同事件

## 常见问题

### 1. 如何测试 Webhook？

使用工具如 [webhook.site](https://webhook.site/) 或 [ngrok](https://ngrok.com/) 进行本地测试。

### 2. 签名验证失败怎么办？

- 检查密钥是否正确
- 确认时间戳在有效范围内
- 验证 payload 是否被修改

### 3. 如何处理大量 Webhook？

- 使用 Queue 进行异步处理
- 增加 Worker 的 CPU 限制
- 考虑使用批量处理
